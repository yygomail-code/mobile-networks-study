> Кому: инженерам Core, отвечающим за классификацию, политики, DPI, безопасность и тарификацию;
> для подготовки к защите. Уровни фильтрации, правила, диагностика, вопросы-ответы.
>
> Связанные файлы: `05_Filtraciya_trafika.md` (краткий), `15_QoS_detalny_konspekt.md` (QoS),
> `21_PS_Core_detalny_konspekt.md` (PS Core), `24_RAN_optimizaciya_detalny_konspekt.md` (RAN).

## 33.1 Что и зачем фильтровать

**Фильтрация трафика** — набор механизмов, которые определяют, **что за трафик** идут,
**как его обрабатывать** (пропустить, ограничить, приоритезировать, заблокировать, посчитать).

Зачем:

- **классификация** для QoS (попадание в нужный bearer/поток);
- **политики и тарификация**: zero-rating, FUP, пакеты услуг;
- **безопасность**: блокировка атак, мошенничества, нежелательного контента;
- **родительский контроль / корпоративные ограничения** (URL/категории);
- **сетевые ограничения**: APN/DNN-политики, роуминг-фильтры;
- **LI (lawful interception)** — по закону, отдельные механизмы.

Принцип: **классифицируй → маркируй → обработай → посчитай**.

## 33.2 Уровни фильтрации (карта)

| Уровень | Где | Что фильтруется |
|---|---|---|
| UE | TFT (4G), QoS rules (5G) | исходящий трафик → bearer/поток |
| RAN | barring, admission (не фильтр трафика) | доступ UE |
| Core — PGW/UPF | SDF/PDR, ACL, NAT, shaping | по 5-tuple, приложениям |
| TDF/DPI | отдельный узел (Sd) или UPF | приложения, URL, категории |
| Граница (SGi/N6) | firewall, NAT, DDoS | IP/порты, аномалии |
| DNS | resolver | домены/категории |
| Контент | прокси/кэш | URL, контент-категории |

## 33.3 Фильтрация в 4G

- **TFT (UL)** — фильтры в UE: 5-tuple (+ DSCP/Flow Label/SPI), precedence; направляют
  пакеты в bearer'ы.
- **SDF-фильтры (DL)** — в PGW: из PCC-правил (**Flow-Information**); определяют, какой
  трафик относится к правилу (и к какому bearer'у).
- **PCC-правила** (PCRF → PGW по Gx): Charging-Rule-Install с Flow-Information, QoS-Information,
  Rating-Group; правила могут быть динамическими (по сигналу AF/Rx) и предустановленными.
- **TDF (Sd)**: DPI-узел детектирует приложения (по сигнатурам/эвристикам) и сообщает PCRF;
  PCRF формирует правила (в т.ч. для zero-rating).
- **ACL/NAT на SGi**: стандартные IP-фильтры шлюза; **GTP firewall** — защита туннелей.
- **APN-политики**: разные APN (internet, ims, corporate) — разные наборы правил.

Пример Flow-Information (VoLTE RTP):

```
permit out 17 from 10.0.0.0/8 1000-2000 to any 5060
```

## 33.4 Фильтрация в 5G

В 5G фильтрация — часть конвейера UPF (N4/PFCP):

| Элемент | Смысл |
|---|---|
| PDR (Packet Detection Rule) | как обнаружить пакет (PDI: 5-tuple, SDF-фильтры, application ID) |
| FAR (Forwarding Action Rule) | что делать (forward/drop/buffer, N6/N9, encapsulate) |
| QER (QoS Enforcement Rule) | QoS: MBR/GBR, gate, QFI |
| URR (Usage Reporting Rule) | учёт: объёмы, события, лимиты |
| BAR (Buffering Action Rule) | буферизация (idle DL) |

- **QoS rules в UE** — UL-классификация (QRI, фильтры, QFI); **reflective QoS** — вывод UL
  правил из DL (RQI).
- **ULCL/BP** — локальная разгрузка (MEC): фильтрация по префиксам/приложениям.
- **URL-фильтрация** — на UPF/N6/прокси (DPI по SNI/HTTP).

## 33.5 DPI/TDF: классификация приложений

- Сигнатуры (паттерны), эвристики, поведенческий анализ, ML.
- Проблемы шифрования: TLS 1.3, ESNI/ECH, QUIC — видно меньше; классификация по SNI/IP/поведению.
- Точность: false positive (чужой трафик в правило) и false negative (правило не сработало) —
  оба влияют на тарификацию и QoS.
- Для zero-rating важна **доказуемость** классификации (риск претензий абонентов).

## 33.6 Политики на основе фильтрации

- **Zero-rating**: трафик приложения не тарифицируется (Rating-Group=0/спец);
- **FUP**: после порога — ограничение (AMBR↓) или блокировка;
- **Родительский контроль**: категории/URL — блокировка/предупреждение;
- **Корпоративные APN**: доступ только к ресурсам компании (ACL/APN-политики);
- **Роуминг**: фильтры на IPX (какие сервисы доступны), APN-OI-Replacement;
- **Anti-DDoS/anti-fraud**: аномалии, rate-limit, чёрные списки;
- **LI**: отдельные правовые механизмы (TS 33.106/33.107), не путать с DPI-политиками.

## 33.7 Диагностика

Типовые проблемы:

1. **Трафик не попадает в bearer/поток** — ошибка TFT/QoS rule (5-tuple, precedence) или
   SDF/PDR-фильтра; симптом: скорость/приоритет не те, что ожидались.
2. **Zero-rating не работает** — DPI не классифицировал (шифрование), правило не установлено,
   Rating-Group не тот; проверять TDF-логи, Gx-правила.
3. **FUP не срабатывает** — OCS/Gy не передал лимит, PCRF не обновил правило.
4. **DPI false positive** — чужой трафик попал под правило; проверять сигнатуры/версии.
5. **GTP firewall режет легитимное** — проверить правила (TEID/IP), логи firewall.
6. **UPF: PDR/FAR не сработали** — проверить N4-сессии (PFCP), порядок правил (precedence),
   счётчики URR.
7. **Симметрия UL/DL** — UL-классификация (UE) и DL (PGW/UPF) настраиваются раздельно;
   рассинхрон — «в одну сторону работает, в другую нет».

Инструменты:

- Wireshark: `gtp`, `pfcp`, `diameter` (Gx/Gy/Sd), `sip`, `tls` (SNI), `dns`;
- счётчики PGW/UPF/TDF: по правилам, URR, FAR; логи классификации;
- тесты: контрольные приложения/протоколы, проверка тарификации (CDR), A/B-проверки.

## 33.8 Вопросы для защиты

**1. Чем TFT отличается от SDF?**
TFT — фильтры **в UE** для UL (какой пакет в какой bearer); SDF — фильтры **в PGW/UPF**
для DL (какой трафик к какому правилу/потоку). Настраиваются раздельно.

**2. Где живёт фильтрация в 5G?**
В конвейере UPF: PDR (обнаружение) → FAR (действие) / QER (QoS) / URR (учёт); в UE —
QoS rules; плюс reflective QoS.

**3. Как zero-rating связан с фильтрацией?**
DPI/TDF классифицирует приложение → PCRF/PCF ставит правило с особым Rating-Group →
PGW/UPF считает иначе → тарификация не списывает.

**4. Почему шифрование ломает DPI?**
TLS 1.3/ECH/QUIC скрывают заголовки; классификация по SNI/IP/поведению менее точна —
растут false negative/positive.

**5. Как проверить, что правило применилось?**
Смотреть Gx/N7 (Charging-Rule-Install), N4 (PDR/FAR/QER), счётчики правил и реальный трафик
(тест-приложение); сверять UL/DL.

**6. Что делать при «в одну сторону не работает»?**
Проверить раздельно UL (TFT/QoS rules в UE) и DL (SDF/PDR в Core); чаще всего настроен
только один из них.

**7. Чем GTP firewall отличается от SGi-firewall?**
GTP — фильтрация внутри мобильного транспорта (туннели, TEID, IP узлов); SGi/N6 — внешний
периметр (IP/порты/атаки).

**8. Как фильтрация влияет на QoS?**
Правильная классификация = правильный bearer/поток = правильный приоритет/полоса;
ошибка классификации — «чужой» класс и неверные KPI.

**9. Что такое ULCL и при чём тут фильтрация?**
Uplink Classifier в UPF направляет часть трафика локально (MEC) по фильтрам/префиксам;
важно для latency и локальных сервисов.

**10. Какие риски у DPI-политик?**
Юридические (недискриминация, приватность), точность классификации, претензии абонентов,
зависимость от версий сигнатур.

- Тарификация: TS 32.299, TS 32.251 (Gy)

## 18.1 Зачем 5G и что в нём нового

IMT-2020 определяет три сценария:

| Сценарий | Что это | Требования (ориентир) |
|---|---|---|
| eMBB | широкополосный доступ | до 10–20 Гбит/с пик, 100 Мбит/с «везде» |
| URLLC | сверхнадёжные задержки | 1 мс, надёжность 99,999% |
| mMTC | массовый IoT | 1 млн устройств/км², 10 лет батарейки |

Что реально нового в 5G по сравнению с 4G:

- **NR (New Radio)** — новое радио: гибкая нумерология, massive MIMO, лучи, mmWave;
- **5GC** — новое ядро на **сервисной архитектуре (SBA)**: облачные функции, REST/HTTP2;
- **слайсинг** — виртуальные сети под разные сервисы (S-NSSAI);
- **QoS flows** — вместо bearer'ов (см. файл 15);
- **MEC** — вычисления на краю сети;
- **SDAP** — новый протокол отображения потоков QoS на радио-каналы.

Важно: 5G — это не только радио. Половина отличий — в ядре, транспорте и эксплуатации.

## 18.2 Архитектура 5G: RAN и ядро

### 18.2.1 gNB и функциональное разделение CU/DU

- **gNB** — базовая станция NR; может быть цельным или разделённым:
  - **gNB-CU** (centralized unit): RRC, SDAP, PDCP;
  - **gNB-DU** (distributed unit): RLC, MAC, физический уровень;
  - интерфейс между ними — **F1** (F1-C управление, F1-U данные).
- Один CU может обслуживать несколько DU (экономия на транспорте, централизация).
- **O-RAN** — открытые интерфейсы между вендорами (Open Fronthaul и др.).

### 18.2.2 5GC: сервисная архитектура (SBA)

Ключевые сетевые функции (NF):

| NF | Роль |
|---|---|
| AMF | доступ и мобильность (аналог MME), NAS-терминация |
| SMF | управление PDU-сессиями (аналог части SGW-C/PGW-C) |
| UPF | пользовательская плоскость (аналог SGW-U/PGW-U) |
| PCF | политики и QoS (аналог PCRF) |
| UDM | данные абонентов (аналог HSS) |
| AUSF | аутентификация |
| NRF | реестр сервисов (service discovery) |
| NSSF | выбор слайса |
| NEF | API для внешних систем |
| CHF | тарификация (аналог OCS/OFCS) |
| AF | приложения (IMS и др.) |

Особенности SBA:

- функции общаются через **сервисные интерфейсы** (HTTP/2 + JSON), а не только по классическим протоколам;
- **NRF** — «справочная»: NF регистрируются и находят друг друга;
- классические интерфейсы (N2, N3, N4) остаются: NGAP, GTP-U, PFCP.

### 18.2.3 Основные интерфейсы 5G

| Интерфейс | Между кем | Протокол |
|---|---|---|
| N1 | UE ↔ AMF (логически) | NAS-5GS |
| N2 | gNB ↔ AMF | NGAP (SCTP) |
| N3 | gNB ↔ UPF | GTP-U |
| N4 | SMF ↔ UPF | PFCP |
| N6 | UPF ↔ внешняя сеть | IP |
| N7 | SMF ↔ PCF | HTTP/2 (SBI) |
| N8 | AMF ↔ UDM | SBI |
| N11 | AMF ↔ SMF | SBI |
| N12/N13 | AMF ↔ AUSF ↔ UDM | SBI |
| N22 | AMF ↔ NSSF | SBI |
| Xn | gNB ↔ gNB | XnAP |
| N32 | SEPP ↔ SEPP (роуминг) | SBI |

## 18.3 Варианты развёртывания (3GPP options)

Исторически 3GPP определил несколько «опций» перехода к 5G:

| Опция | Название | Якорь | Ядро | Суть |
|---|---|---|---|---|
| 2 | SA | NR | 5GC | автономный 5G «с нуля» |
| 3/3a/3x | EN-DC (NSA) | LTE (eNB) | EPC | NR как «усилитель» к LTE |
| 4/4a | NE-DC | NR | 5GC | NR — якорь, LTE — добавка |
| 5 | eLTE | LTE | 5GC | LTE подключён к 5GC (без NR) |
| 7/7a/7x | NGEN-DC | LTE (eNB) | 5GC | LTE-якорь, но ядро уже 5GC |

На практике:

- **Option 3x** — самый распространённый первый шаг (NSA): быстро, на существующем EPC;
- **Option 2 (SA)** — целевая архитектура: слайсинг, URLLC, VoNR, SBA;
- **Option 7x** — промежуточный шаг: LTE-якорь + 5GC;
- **DSS** — не опция, а способ делить спектр LTE/NR (см. 18.6).

## 18.4 NSA: EN-DC в деталях

### 18.4.1 Архитектура EN-DC

- **MN (Master Node)** = eNB (LTE): управление, якорь, сигнализация;
- **SN (Secondary Node)** = gNB (NR): дополнительная ёмкость;
- ядро — **EPC**: MME, SGW, PGW (как в 4G);
- интерфейсы:
  - **Uu LTE** и **Uu NR** — радио к обоим узлам;
  - **X2-C / X2-U** — между eNB и gNB (управление и данные);
  - **S1-MME** (eNB↔MME), **S1-U** (eNB↔SGW), **S5/S8** (SGW↔PGW);
- UE работает в **двойном соединении**: LTE + NR одновременно.

Типы bearer'ов в EN-DC:

- **MCG bearer** — данные только через eNB;
- **SCG bearer** — данные только через gNB (вариант 3a);
- **split bearer** — данные через оба узла (3/3x), PDCP на якоре.

### 18.4.2 Процедуры NSA

1. UE подключается к LTE (attach, default bearer) — как обычно.
2. Сеть узнаёт из **UE Capability**, что телефон умеет EN-DC (Bands, EN-DC combo).
3. eNB настраивает **измерения NR (event B1)**: «луч NR стал лучше порога».
4. UE сообщает B1 → eNB отправляет **SgNB Addition Request** по X2.
5. gNB отвечает (ресурсы, конфигурация NR) → **RRC Reconfiguration** на UE.
6. UE выполняет **Random Access в NR**, добавляется SCG → **SgNB Addition Complete**.
7. Трафик идёт через LTE и/или NR (split/SCG). Управление — всегда через LTE.

Изменение/удаление: SgNB Modification, SgNB Change (смена NR-узла), SgNB Release.
Событие **B2** используется для переключения/удаления NR.

### 18.4.3 Ограничения NSA

- зависимость от покрытия LTE-якоря (нет LTE — нет 5G);
- EPC не умеет слайсинг/SBA (часть возможностей 5G недоступна);
- голос — только VoLTE по LTE (VoNR в NSA нет);
- выше расход батареи (два передатчика), сложнее UL;
- требования к задержке X2 (транспорт между eNB и gNB).

## 18.5 SA: автономная архитектура

### 18.5.1 Что меняется

- gNB подключается к **5GC**: N2 → AMF, N3 → UPF;
- нет LTE-якоря: управление и данные — на NR;
- NAS нового поколения (5G NAS) между UE и AMF;
- полный набор возможностей: слайсинг, MEC, VoNR, SBA, сетевые API.

### 18.5.2 Процедуры SA

**Регистрация (Registration):**

1. UE → gNB → AMF: Registration Request (SUCI, capabilities, requested NSSAI).
2. Выбор AMF (по NSSAI, NRF), аутентификация (AUSF/UDM), NAS Security.
3. AMF получает подписку (UDM), регистрирует UE (RM-REGISTERED).
4. Registration Accept (allocated 5G-GUTI, TAI list, allowed NSSAI).

**Состояния:**

- RM: RM-DEREGISTERED ↔ RM-REGISTERED;
- CM: CM-IDLE ↔ CM-CONNECTED (управление соединением);
- RRC: RRC_IDLE, RRC_INACTIVE (новое состояние), RRC_CONNECTED.

**PDU-сессия (данные):**

1. UE: PDU Session Establishment Request (DNN, S-NSSAI, PDU type).
2. AMF выбирает SMF → SMF выбирает UPF.
3. SMF программирует UPF (N4/PFCP), gNB получает N2 (PDU Session Resource Setup).
4. UE получает PDU Session Establishment Accept + QoS rules.

**Мобильность:** Xn-handover (gNB↔gNB напрямую), N2-handover (через AMF); inter-RAT NR↔LTE.

### 18.5.3 Слайсинг и MEC

- **Слайс** = S-NSSAI (SST + SD): например, eMBB (SST=1), URLLC (2), MIoT (3);
- **NSSF** помогает выбрать AMF/слайс; слайс влияет на QoS, политики, иногда на ядро целиком;
- **MEC** — приложения у края сети: локальная разгрузка (ULCL), низкая задержка;
- роуминг: home-routed (через HPLMN) и local breakout; безопасность — **SEPP** (N32).

## 18.6 DSS: динамическое разделение спектра

### 18.6.1 Идея и механика

**DSS (Dynamic Spectrum Sharing)** — LTE и NR одновременно работают в **одной и той же несущей**:

- NR планирует ресурсы **только там**, где их не занимает LTE (динамически, по слотам);
- NR **обходит LTE CRS** (опорные сигналы): rate matching вокруг CRS;
- **SSB NR передаётся в MBSFN-субкадрах LTE** (зарезервированы под NR);
- нумерология NR выравнивается: **SCS 15 кГц**, совместимые сетки ресурсных блоков;
- координация — на уровне планировщика (одна платформа или быстрый обмен).

### 18.6.2 Плюсы и минусы

| Плюсы | Минусы |
|---|---|
| Быстрое покрытие 5G без нового спектра | Потеря ёмкости (CRS, координация) |
| Плавная миграция, один слой оборудования | Пиковые скорости NR ниже, чем на выделенной несущей |
| Работает в низких/средних диапазонах (700–2600 МГц) | Ограничения функций NR (не всё доступно) |
| Единое покрытие LTE и NR | Требует зрелого ПО и точной настройки |

Типичное применение — переходный период: пока нет отдельного спектра под NR,
DSS даёт «пятёрку» на существующей сетке.

### 18.6.3 Влияние на KPI

- LTE: возможен просадок скорости и рост задержек при активном NR;
- NR: скорость ограничена доступными ресурсами;
- важно мониторить: долю ресурсов NR/LTE, PRB utilization, качество обоих слоёв,
  балансировку и параметры координации.

## 18.7 Спектр и радио 5G

- **Диапазоны:** FR1 (410 МГц – 7,125 ГГц), FR2 (24,25–71 ГГц);
  рабочие: n28/n8/n1/n3 (низкие), n78/n77/n41 (средние), n257/n258/n260/n261 (mmWave).
- **Полосы:** 5–20 МГц (низкие), 40–100 МГц (средние), до 400 МГц (mmWave).
- **Нумерология (SCS):** 15 / 30 / 60 / 120 кГц; слот: 1 / 0,5 / 0,25 / 0,125 мс.
- **TDD** — основной режим средних диапазонов: гибкая структура кадра (D/U/flexible),
  SSB-бёрсты, beam sweeping.
- **Massive MIMO:** 32T32R/64T64R, формирование лучей, MU-MIMO; покрытие и ёмкость.
- **SUL** (supplementary uplink) — дополнительный восходящий канал в низком диапазоне
  для улучшения UL-покрытия.

## 18.8 Голос в 5G

- **NSA:** голос всегда через LTE (VoLTE); NR — только данные.
- **SA: VoNR** — голос как QoS flow 5QI 1 поверх 5GC; IMS-сигнализация — 5QI 5;
  кодек EVS; требования к покрытию NR и настройке IMS.
- **EPS Fallback** — если VoNR недоступен (нет покрытия/настроек):
  1. UE регистрируется в 5GC, IMS-voice флаг сообщает о поддержке;
  2. при входящем/исходящем вызове IMS запрашивает установление голосового носителя;
  3. сеть переводит UE в LTE (handover или redirection) — **до** установления вызова;
  4. вызов идёт как VoLTE; после — UE может вернуться в NR.
- **SMS:** over NAS (5G) или over IMS.
- **Экстренные вызовы:** через VoLTE/VoNR или fallback — по конфигурации сети.

## 18.9 Переходы и сосуществование

- **NSA → SA:** перевод gNB на 5GC (dual-mode), миграция абонентов, отключение LTE-якоря;
- **N26** — интерфейс AMF↔MME: бесшовность при переходах NR↔LTE (контекст, сессии);
- **Inter-RAT handover:** NR→LTE (для голоса/покрытия), LTE→NR (для скорости);
- **UE-возможности:** NSA-only, SA-only, обе — от этого зависит поведение в сети;
- **Агрегация:** EN-DC (LTE+NR), NR-CA (несколько NR-несущих), UL-агрегация;
- **DSS** — мост на время, пока спектр не разделён.

## 18.10 Практика: развёртывание и KPI

Типовые стратегии:

| Задача | Решение |
|---|---|
| Быстрый запуск 5G | NSA (Option 3x) на существующем EPC |
| Слайсинг/URLLC/VoNR | SA (Option 2) |
| Покрытие без нового спектра | DSS |
| Промежуточный шаг | Option 7x (LTE-якорь + 5GC) |

KPI:

- доступность: registration success rate, PDU session success rate;
- удержание: drop rate, handover success (Xn/N2, inter-RAT);
- производительность: DL/UL throughput, latency, PRB utilization;
- NSA: SgNB Addition Success Rate, доля времени с NR (NR coverage/time);
- голос: VoNR/EPS fallback success, setup time, MOS;
- UE: распределение по возможностям (EN-DC/SA), отказы по capability.

## 18.11 Диагностика

### 18.11.1 По слоям

| Слой | Что смотреть |
|---|---|
| UE | возможности (EN-DC/SA), RRC/NAS-состояния, измерения NR |
| RAN | RRC-конфигурация, X2/Xn, B1/B2, beam/SSB, PRB, ошибки RA |
| Core | N2 (NGAP), регистрация/NSSAI, N4 (PFCP), выбор UPF/SMF |
| IMS | голос: VoNR/EPS fallback, N26, IMS-регистрация |

### 18.11.2 Типовые проблемы

1. **UE не регистрируется в SA** — rejected NSSAI, неверный AMF/слайс, подписка.
2. **PDU-сессия не устанавливается** — SMF/UPF (N4), DNN, политика, ресурсы.
3. **EN-DC не добавляется** — порог B1, X2-транспорт, перегрузка gNB, capability.
4. **Голос не работает** — нет VoNR и не сработал EPS fallback (N26, IMS-флаг).
5. **Скорость упала после DSS** — координация LTE/NR, CRS-потери, дисбаланс ресурсов.
6. **Handover NR→LTE падает** — измерения, N2/N26, конфигурация соседей.

### 18.11.3 Инструменты

- трассировки: gNB, AMF, SMF, UPF, IMS;
- Wireshark: `ngap`, `pfcp`, `nas-5gs`, `gtp`, `x2ap`, `s1ap`;
- счётчики и KPI по gNB/слоям; тесты на реальных UE разных категорий;
- драйв-тесты: покрытие NR, скорость, переключения, голос.

## 18.13 Мини-словарь

- **NR** — радио 5G; **gNB** — базовая станция NR.
- **SA / NSA** — автономный / неавтономный 5G.
- **EN-DC** — двойное соединение LTE+NR (NSA).
- **MN / SN** — ведущий / вторичный узел двойного соединения.
- **SgNB** — gNB в роли вторичного узла.
- **X2 / Xn** — интерфейсы между базовыми станциями (LTE / NR).
- **SBA** — сервисная архитектура ядра; **NRF** — реестр сервисов.
- **PDU-сессия** — аналог «сессии данных» в 5G.
- **S-NSSAI** — идентификатор слайса.
- **DSS** — динамическое разделение спектра LTE/NR.
- **B1/B2** — события измерений NR (добавление/смена узла).
- **EPS Fallback** — перевод в LTE для голоса.
- **N26** — интерфейс AMF↔MME для переходов.
- **CU/DU** — центральный/распределённый блок gNB (F1).
- **RRC_INACTIVE** — «спящее» состояние с сохранением контекста.
